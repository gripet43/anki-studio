## 第三步：静态测试套（README 新增命令）

本轮首次执行 README「自动化测试与体检」的两组命令，两组在 Windows 干净环境里都
没能直接跑通，问题均定位到测试/构建工具链，**不是产品功能缺陷**。

### 3.1 `node tests/test_frontend_bundle.mjs`

- 仓库直接跑：失败于 `Item #33: 解析 ZH_CN 基准字典失败（解析到 0 条）`。
- 根因：本机 `git config core.autocrlf=true`，`frontend/src/i18n/translations.ts`
  工作区为 1560 行全 CRLF；守卫 `test_frontend_bundle.mjs:614-628` 的
  `parseFlatDict()` 用 `body.split('\n')` 后套 `/^ {2}(\w+):\s*(['"])(.*)\2,?$/`，
  行尾残留 `\r` 使每行都不匹配 → 0 条。起始标记与结束标记本身都在，不是字典内容问题。
- 交叉验证：用 `git archive HEAD` 建 LF 副本并强制把 118 个文本文件的换行归一为 LF，
  同一脚本输出 `[Part 1 Guardrails + 9 UX Enhancements Audit Suite] ALL CHECKS PASSED!`。
  即守卫的 35 项断言本身是全绿的，只是 Windows checkout 下解析失效。
- `git show HEAD:...` 确认仓库 blob 是 LF（0 个 CRLF），问题只发生在工作区。

### 3.2 `python -m unittest discover -s tests -p "test_*.py" -v`

- 直接跑：`test_bridge` / `test_card_safety` / `test_card_safety_round3` 三个模块
  `ModuleNotFoundError: No module named 'anki_modern_os'`。因为
  `safety_harness.py:29` 与 `test_bridge.py:34` 执行
  `sys.path.insert(0, ADDON_ROOT.parent)` 后导入固定包名，要求仓库目录就叫
  `anki_modern_os`；本机 clone 目录是 `anki-studio`。
- 变通：在仓库外用目录联接 `Anki-Test-Env\wb\shim\anki_modern_os → anki-studio`
  并以 `PYTHONPATH` 指向它，测试即能加载。
- 结果：**Ran 43 tests，42 通过，1 error**：
  `test_card_safety_round3.py:174` 断言 `child.exitcode == -signal.SIGKILL`，
  Windows 的 `signal` 模块没有 `SIGKILL` → `AttributeError`。
- 另有两条子进程噪声 `[Anki Studio] Error writing to native clipboard: No module named 'aqt'`，
  不参与判定。
- `tests/test_release_safety.py` 的 6 项（manifest YYMMDD 口径、human_version、
  homepage 非占位、bridge 无裸 SQL 写库、profile_did_open 钩子）全部通过。

### 3.3 打包 `scripts/build_ankiaddon.py`

- 默认路径失败：`run_frontend_build()` 用 `subprocess.run(["npm", "run", "build"])`，
  Windows 的 `CreateProcess` 找不到 `npm`（需要 `npm.cmd`），报 `FileNotFoundError [WinError 2]`；
  且本机 `frontend/node_modules` 不存在，前端也无法现编。
- 用 `--skip-build` 绕过后仍失败：`TOP_LEVEL_FILES` 含 `config.json`，
  `build_ankiaddon.py:124` 强制要求该文件存在；但同函数 line 137 的注释与实现又
  明确「源码仓库里的 config.json 已不入库，优先读 config.default.json 干净模板」。
  两者矛盾，干净 clone 必然卡在检查阶段。
- 补一份 `config.json` 后 `--skip-build` 成功：`manifest: v1.4.0 mod=… min_point_version=260904`，
  产出 440,003 B / 30 个运行时文件。校验结果：顶层仅
  `__init__.py / manifest.json / config.json / config.md / bridge / web`，无包裹目录；
  `meta.json` / `frontend/` / `tests/` / `scripts/` / `__pycache__` / `.pyc` 均为 0；
  `config.json` 只保留 9 个公共键，私人字段零残留；`manifest.json` 的 `mod` 已刷新、
  `human_version=1.4.0`、`homepage` 为真实 GitHub 地址。
- 所有打包实验都在仓库外的 LF 副本中进行，仓库 `git status` 保持干净。

## 发现的问题

### 1. 前端守卫在 Windows CRLF checkout 下必然误报 — 不阻断产品，阻断 Windows 验收

- 现象：`node tests/test_frontend_bundle.mjs` 报 `Item #33 解析 ZH_CN 基准字典失败（解析到 0 条）`。
- 复现：任意 Windows 机器 `core.autocrlf=true` clone 后直接跑；改 LF 即全绿。
- 定位：`tests/test_frontend_bundle.mjs:614-628`，正则未考虑 `\r`。
- 截图/证据：本文件 3.1 节；无界面截图（纯静态守卫）。
- 是否阻断发布：**否**（产品代码无缺陷），但 README「两组都必须全绿」在 Windows 上做不到。

### 2. Python 单元测试硬编码包目录名 — 不阻断产品，阻断 Windows 验收

- 现象：干净 clone 到 `anki-studio` 后，3 个模块 `ModuleNotFoundError: anki_modern_os`。
- 复现：`python -m unittest discover -s tests -p "test_*.py"`，仓库目录名不是 `anki_modern_os`。
- 定位：`tests/safety_harness.py:29`、`tests/test_bridge.py:34`；文档未写明目录名要求。
- 变通：目录联接 + `PYTHONPATH`（本轮已用）。
- 是否阻断发布：**否**，但应补文档或改为相对导入。

### 3. `test_card_safety_round3.py` 依赖 POSIX `SIGKILL` — 不阻断产品

- 现象：43 项中 1 error，`AttributeError: module 'signal' has no attribute 'SIGKILL'`。
- 定位：`tests/test_card_safety_round3.py:174`。
- 是否阻断发布：**否**，属测试套件平台兼容性缺口；Windows 侧该崩溃恢复用例实际未覆盖。

### 4. `build_ankiaddon.py` 在干净 clone 下无法打包 — 阻断干净环境发布流程

- 现象 A：`npm` 调用 `FileNotFoundError [WinError 2]`（Windows 需 `npm.cmd`），
  且本机无 `frontend/node_modules`。
- 现象 B：即使用 `--skip-build`，仍报 `Required top-level file missing: config.json`。
- 定位：`scripts/build_ankiaddon.py:28-33` 的 `TOP_LEVEL_FILES` 与 line 124 的
  存在性检查，和 line 137「config.json 已不入库、优先读 config.default.json」自相矛盾。
- 变通：补一份 `config.json` 后打包成功（30 文件 / 白名单与脱敏全部正确）。
- 是否阻断发布：**对干净 CI/新机器是阻断的**。macOS 开发机本地有 `config.json`
  与 `node_modules`，所以实际发布路径不会撞上；仍建议修脚本，让它按注释直接用
  `config.default.json`。

### 5. 前端守卫 Item #34 只检查 `.ankiaddon` 是否存在 — 不阻断产品，守卫有效性不足

- 现象：问题 4 的失败发生在 `zipfile.ZipFile(..., "w")` 已创建文件之后，
  留下 9,866 字节的**半成品包**；此时 `node tests/test_frontend_bundle.mjs`
  的 `fs.existsSync(ANKIADDON_FILE)` 依然为真，守卫一路放行。
- 复现：干净 clone 跑打包失败 → 立刻跑守卫。
- 定位：`tests/test_frontend_bundle.mjs:707-715`。
- 是否阻断发布：**否**，但会让「构建产物有效」这一断言形同虚设。

### 6. B3 两个子态无法目视 — 环境限制，与 r4 一致

- 已验证：未同步主题色云朵、悬停快照浮窗。
- 未验证：已同步态的云朵配色、同步进行中的橙色脉冲点。沙盒无 AnkiWeb 凭据，
  点击同步会弹原生登录模态框（`IsWindowEnabled=0` 导致后续点击被吞，需 Esc 关闭）。
- 代码层确认：`SyncStatusPill.tsx:152` 橙色 `animate-ping` 圆点、`:161` `animate-pulse`
  文案、`:243` 云端同步浮窗标题均在。
- 是否阻断发布：**否**（与操作系统无关，属测试环境缺口）。

### 7. QEMU 输入层首次点击被吞 / 双击穿透 — 测试机现象，非产品缺陷

- 现象：新启动 Anki 后首次点击只激活窗口；用 `times=2` 快速双击旗标菜单项时，
  第一次关掉菜单、第二次穿透到下层卡片，误开「编辑卡片」弹窗

- 处理：先关闭误开弹窗、重新打开菜单、再单击，C1 随即通过。
- 是否阻断发布：**否**，r4 已记录同类现象。
