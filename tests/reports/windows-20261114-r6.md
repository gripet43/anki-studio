## 发现的问题

### 1. `test_card_safety_round3.py` 崩溃用例在 Windows 上必然 error — 阻断 Windows 门禁

- 现象：`python -m unittest discover -s tests -p "test_*.py"` →
  `Ran 141 tests … FAILED (errors=1)`；`PermissionError: [WinError 32]
  另一个程序正在使用此文件` 发生在 `with tempfile.TemporaryDirectory(...)` 退出清理时。
  单独跑 `discover -p "test_card_safety_round3.py"` 稳定复现（4 tests / 1 error）。
- 定位：`tests/test_card_safety_round3.py:175` 的 `test_02_sigkill_crash_…`
  在 line 220 用 `SafetyEnv.from_files(db_path, cfg_path)` 重新打开 collection，
  但**全程没有 `env.close()`**。Anki 的 Rust 后端持有 `collection.anki2` 文件句柄；
  POSIX 允许删除已打开的文件，Windows 不允许，于是临时目录清理失败。
  上轮报的是 `signal.SIGKILL` 缺失，这次断言已改成条件分支，等于把下一个
  Windows 平台差异暴露了出来。
- 影响：`gate.sh --with-project` 第 6 步被 `pipefail` 判失败，整条门禁 EXIT=1。
- 是否阻断发布：**否**（产品代码无缺陷，崩溃恢复语义的断言在清理前已全部执行），
  但「Windows 上一键门禁全绿」做不到，属测试套件平台兼容缺口。

### 2. `build_ankiaddon.py` 干净 clone 仍打不出包 — 只修了一半

- 现象 A（**已修**）：`e8447ce` 加 `_npm_executable()`，`shutil.which("npm")`
  在 Windows 解析到 `npm.CMD`，Vite 生产构建成功（85 modules / 6.05s），
  不再 `FileNotFoundError [WinError 2]`。
- 现象 B（**未修**）：紧接着 `FileNotFoundError: Required top-level file missing:
  C:\Users\11\Projects\anki-studio\config.json`。
  `scripts/build_ankiaddon.py:34-39` 的 `TOP_LEVEL_FILES` 含 `config.json`，
  line 151-152 无条件检查它存在；但 `.gitignore:24` 明确忽略 `config.json`，
  line 161-164 的注释与实现又说「已不入库，优先读 config.default.json」。
  两处逻辑依旧自相矛盾。
- 变通：`cp config.default.json config.json` 后 `python scripts/build_ankiaddon.py
  --skip-build --no-downloads` 成功 → 32 个运行时文件 / 508,735 B /
  SHA-256 `6ef91db6…`；顶层只有 `__init__.py / manifest.json / config.json /
  config.md / bridge / web`，`meta.json` / `frontend` / `tests` / `scripts` /
  `__pycache__` / `.pyc` 全部为 0，`config.json` 仅 9 个公共键、私人字段零残留，
  `manifest.json` v1.5.7 / `mod` 已刷新 / `min_point_version=260904`。
- 是否阻断发布：**对干净 CI / 新机器是阻断的**；macOS 开发机本地有 `config.json`
  所以实际发布路径不撞。建议让检查按注释直接读 `config.default.json`。

### 5. Windows 上前端重建会改写仓库产物的行尾 — 构建流程副作用

- `npm install` 会把 `frontend/package-lock.json` 改脏；`npm run build` 把
  17 个 `web/assets/*` + `web/index.html` 全部标 M。
- 定位：`core.autocrlf=true` checkout 出 CRLF，Vite 写出 LF；
  `git diff --ignore-space-at-eol --stat -- web/assets/index.js` 为空，
  说明**内容逐字节一致，纯粹是行尾差异**。
- 处理：本轮测完 `git checkout -- web/ frontend/package-lock.json` 还原，
  仓库最终干净。建议发版机统一用 LF 或给 `web/` 加 `.gitattributes`。
