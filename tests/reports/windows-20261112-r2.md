## 本轮新发现的问题

### 1. 深色模式下次级文字与图表数值对比度偏低

- 现象：切到深色后，主标题、卡片正文清晰；但「过去 12 周…」类副标题、侧栏牌组计数、
  统计图的百分比标签（87.3%、88.9% 等）呈深蓝压深灰，需凑近才能读清。
- 复现：设置 → 外观与语言 → 主题模式「深色」→ 打开学习统计。
- 截图：`08-dark.png`（对照 `06-stats.png` 浅色）
- 是否阻断发布：否。建议给 `text-muted` / 图表 axis label 在 dark 主题下单独提亮。

### 2. 快捷键清单在 Windows 上仍写 `Cmd`，与说明和实际按键不符

- 现象：设置 → 快捷键 页面顶部写着「根据当前操作系统自动适配 Cmd (macOS) 与 Ctrl (Windows / Linux)」，
  但条目实际显示 **`Cmd + K`**（全局搜索）和 **`Cmd + Z`**（撤销）；本机实测 `Ctrl+K` / `Ctrl+Z`
  才生效。同一页里「原生切换」又正确显示为 `Ctrl + Alt + M`，说明是部分条目漏了平台判断。
- 另一处不一致：清单写复习评分「困难 / 简单 2 / 3 / 4」，而复习界面实际只有「遗忘 / 记得」两个按钮
  （`04-review-back.png`），键位提示与界面不符。
- 复现：设置 → 快捷键，或复习界面按 2/3/4。
- 截图：`16-shortcuts.png`、`04-review-back.png`
- 是否阻断发布：否，但属于指导书第 8 项「快捷键与界面提示一致」的文案缺口，建议修。

### 3. `get_dashboard` 在 3000 卡量级仍约 0.76 s；新聚合 SQL 有约 10% 回退

- 现象：`13b9a59` 把四阶段构成合并成单条 SQL 后，3020 卡的 `get_dashboard` 中位数从
  `c621dbd` 的 685 ms 回到 763 ms（+11%）；20022 卡从 1436 ms 到 1514 ms（+5%）。
  3020 卡量级与第一轮基本持平（759 → 763 ms），20022 卡量级比第一轮的 1748 ms 改善约 13%，
  主要收益来自 `get_statistics` 的查询合并（754 → 575 ms，-24%）。
- 复现：第五步计时脚本，静默环境各跑 3 次取中位数。
- 是否阻断发布：否。首页后端 0.76 s 对 3000 卡账号仍偏高，建议继续看是否能在首屏只取摘要。

### 4. 计时数据受机器负载影响很大（测量方法提示，非产品缺陷）

- 现象：Anki GUI 与 `build.py` 并发时，20000 卡构建从 52 s 涨到 145 s，所有 action 耗时约翻倍
  （连未改动的 `search_cards` 也从 255 ms 涨到 500–700 ms）。关闭 Anki 后数值回到正常区间。
- 结论：本报告采用**关闭 GUI 后的静默环境**数据；后续在 Windows 上做性能对比务必固定这个前提。
